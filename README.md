# Карточки по математическому анализу

Это мой небольшой pet-проект: почти сотня карточек для подготовки к коллоквиуму по матану. Я собрал определения, теоремы с идеями доказательств, аксиомы и схемы в одном месте, чтобы не листать десятки страниц конспекта. Открываете карточку, вспоминаете формулировку, переворачиваете — и сверяетесь с ответом. Всё работает в браузере, без регистрации и установки.

**Сайт:** https://antyklays.github.io/math-cards/  
**Мини-игра:** https://antyklays.github.io/math-cards/game.html

## Что внутри

- **97 карточек в 13 разделах** — от множеств и отображений до пределов последовательностей.
- **Определения, теоремы и аксиомы** — у теорем есть не только формулировки, но и идеи доказательств.
- **73 SVG-схемы** — открываются по клику в полный размер.
- **Прогресс и избранное** — выученные карточки подсвечиваются, а сложные можно отложить в отдельный список.
- **Мини-игра** — три режима: экзамен, марафон и учёба.
- **Тетрадный стиль** — клетка, рукописные заголовки и цветные пометки. Мне хотелось, чтобы сайт выглядел как конспект, а не как очередной веб-сервис.

## Как готовиться

1. Откройте [сайт](https://antyklays.github.io/math-cards/).
2. Прочитайте название карточки и попробуйте сформулировать ответ вслух.
3. Нажмите на карточку и сверьтесь с текстом, схемой и доказательством.
4. Если ответ сошёлся, нажмите «Выучил» — карточка станет зелёной.
5. Сложные темы добавляйте в избранное звёздочкой ☆, чтобы вернуться к ним позже.

## Мини-игра

В `game.html` те же карточки, но в виде игры. Я сделал три режима:

- ◎ **Экзамен** — 9 карточек, 3 жизни, очки и зачёты. Карточки подбираются с учётом ошибок: то, что даётся хуже, попадается чаще.
- ∞ **Марафон** — все карточки в случайном порядке, 3 жизни.
- ✎ **Учёба** — без жизней и очков, можно листать в обе стороны.

Карточка переворачивается кликом или пробелом. Ответить можно свайпом, кнопками «Не знаю / Знаю» или стрелками ← →. Схемы открываются по клику, Esc ставит игру на паузу.

## Запуск локально

Сайт статический, но карточки загружаются из `mathAnal.json` через `fetch`. Поэтому просто открыть `index.html` двойным щелчком не получится — браузер заблокирует загрузку. Запустите локальный сервер в папке проекта:

```bash
python -m http.server 8000
```

И откройте:

- http://localhost:8000/ — карточки;
- http://localhost:8000/game.html — мини-игра.

## Как добавить или поправить карточку

Все карточки лежат в `mathAnal.json`, внутри `sections[].cards[]`. Одна карточка выглядит так:

```json
{
  "id": "mathan-1-001-mnozhestvo-i-ego-elementy",
  "title": "Множество и его элементы",
  "type": "def",
  "content": "Множество — совокупность объектов...",
  "note": "Примеры числовых множеств: ℕ, ℚ, ℤ, ℝ.",
  "sort_order": 1,
  "images": [
    {
      "url": "cards-visuals/matan/01-set-elements.svg",
      "alt": "Точки a и b внутри множества A",
      "caption": "Принадлежность множеству"
    }
  ]
}
```

`type` может быть `def` (определение), `thm` (теорема), `ax` (аксиома) или `other`. У базы и разделов тоже есть обязательные поля (`schema_version`, `id`, `title`, `sort_order`), но их проще подсмотреть в существующем файле. Схемы складывайте в `cards-visuals/matan/`.

Перед коммитом проверьте базу:

```bash
node validate-cards-database.js mathAnal.json
```

Скрипт проверит структуру, `id`, `sort_order` и картинки — и скажет, если что-то не сходится.

## Публикация

Сайт живёт на GitHub Pages: ветка `main`, корень репозитория. После пуша в `main` страница обновится сама — обычно в течение минуты. Файл `.nojekyll` нужен, чтобы GitHub Pages не обрабатывал файлы через Jekyll.

## Полезно знать

- Прогресс, избранное и статистика игры хранятся в `localStorage`. У каждого браузера и устройства они свои — между устройствами не синхронизируются.
- В просмотрщике есть режим редактирования (⚙), но он сохраняет изменения только в этом браузере. Чтобы изменить базу для всех, правьте `mathAnal.json`.
- Шрифты подтягиваются из Google Fonts. Без интернета сайт продолжит работать, но покажет системные шрифты.
- Карточки собраны по расшифровкам лекций 1–8. Это конспект, а не учебник: если формулировка расходится с первоисточником, доверяйте первоисточнику.
- Если заметите опечатку или ошибку — создайте issue или пришлите pull request. Свежий взгляд всегда полезен.
